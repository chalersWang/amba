# A5: 事务标识符 (Transaction Identifiers)

## 5.1 ID 信号

| 信号 | 说明 |
|------|------|
| AWID | 写事务 ID |
| ARID | 读事务 ID |
| WID | 写数据 ID（AXI3 独有，AXI4 已移除） |
| BID | 写响应 ID（与 AWID 匹配） |
| RID | 读数据 ID（与 ARID 匹配） |

## 5.2 ID 用途

- 标识不同的事务流，支持乱序完成
- 相同 ID 的事务必须按顺序完成
- 不同 ID 的事务可以任意顺序完成

## 5.3 乱序事务

### 写事务乱序
- 不同 AWID 的写事务可以乱序完成
- 互连可以重排序写事务以提高带宽利用率

### 读事务乱序
- 不同 ARID 的读事务可以乱序返回数据
- Subordinate 可以在处理读事务时交错响应

## 5.4 ID 宽度

- 典型 ID 宽度：4-16 位
- Manager 支持的 ID 数量影响其处理乱序事务的能力
- 互连可能需要增加 ID 位宽以支持路由

## 5.5 排序规则总结

| 场景 | 排序要求 |
|------|----------|
| 相同 AWID 写事务 | 按发送顺序完成 |
| 相同 ARID 读事务 | 按发送顺序返回 |
| 不同 ID 事务 | 可乱序 |
| 读-写依赖 | 由 Manager 通过等待前序事务完成来保证 |
