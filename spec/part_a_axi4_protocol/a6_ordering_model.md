# A6: 排序模型 (Ordering Model)

## 6.1 基本排序原则

- AXI4 使用 ID 标签区分事务流
- 相同 ID 的事务按顺序完成
- 不同 ID 的事务无排序要求
- 读写事务之间无固有的排序关系

## 6.2 写-写排序

- 相同 AWID 的写事务：严格按地址通道发送顺序完成
- 不同 AWID 的写事务：可乱序完成
- 写响应（B 通道）的返回顺序反映实际完成顺序

## 6.3 读-读排序

- 相同 ARID 的读事务：数据按发放顺序返回
- 不同 ARID 的读事务：数据可乱序返回
- RLAST 标识 burst 最后一拍

## 6.4 读写交织

```
Manager 视角：
  写事务 AW(W1) → W(W1) → B(W1)
                        ↓
  读事务 AR(R1) ──────────→ R(R1)

  - W1 的写数据在 R1 的读数据之前发出
  - 但不保证 Subordinate 看到 W1 的结果后再响应 R1
  - 如需保证，Manager 必须等待 B(W1) 后再发出 AR(R1)
```

## 6.5 事务交织限制

- AXI4 不支持 W 通道上的事务交织
- 一个写事务的所有 W 数据必须在下一个写事务的 W 数据之前完成
- AXI3 通过 WID 支持 W 通道交织，AXI4 移除了此功能

## 6.6 排序保证总结

| 事务对 | 相同 ID | 不同 ID |
|--------|---------|---------|
| 写 → 写 | 有序 | 无序 |
| 读 → 读 | 有序 | 无序 |
| 写 → 读 | 无保证 | 无保证 |
| 读 → 写 | 无保证 | 无保证 |
